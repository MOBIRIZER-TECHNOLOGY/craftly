# Browser journeys

Scripted end-to-end checks that drive the real app in Chrome (through `playwright-core`; no browser is downloaded, a local Chrome, Edge or Chromium is used). They click through the interface the way a person would and read the document store (`window.__editor`) to confirm the result.

```bash
npm run dev            # in one terminal: http://127.0.0.1:5173
npm run e2e            # in another: runs every journey, exits non-zero on a failure
```

| Journey | Covers |
| --- | --- |
| `journey.cjs` | create a design, insert shapes / photos / graphics / charts / tables / lines / frames, undo / redo (buttons and keys), select all / group / ungroup / duplicate / delete, nudging, headings, add / duplicate / go to pages, apply a template (whole deck and one page, with undo), download PNG / PDF / SVG / JPG and check the file signatures, autosave and reload, reopen from Recent designs |
| `features.cjs` | text size, styles, font family, colour, alignment, lists, case, spacing, effects and curve; Position panel (arrange, align); layers (order, lock, hide); uploads; crop; image filters and flip; Replace; page background; zoom; rulers and guides; Resize; Find and replace; Present; reorder and delete pages |
| `animate.cjs` | Animate panel: entrance / exit / emphasis per element, direction, duration and delay, page animations (staggered), page duration, transitions (and "apply to all pages"), the canvas preview and Esc, undo / redo, persistence across a reload, templates that ship with motion |
| `present.cjs` | the full-screen show reads the presenter's canvas pixels: an entrance plays (not there at the first frame, part-way, then there), Right plays the page's transition and Left plays it backwards, `P` and the Auto-play button start and stop the show on its own (progress line, advances by itself, stops after the last page, Next turns it off), reduced motion makes moves instant cuts, Esc leaves the editor on the page the show ended on |
| `animated-export.cjs` | Download panel with Animated GIF and Video (WebM): the options and length it shows, a GIF read block by block (size, frames, the delays add up to the length, loops for ever) and decoded by Chrome (same frame count, first frame is page 1 and last frame is page 2), a WebM read back in a `<video>` (finite duration, size, first and last frame), Cancel while a video records, and the hint on a design with nothing animated |
| `ml.cjs` | the on-device photo tools without downloading a model (the GPU steps skip themselves where the browser has no WebGPU adapter, as on most CI machines): the Tools tab (Remove background, Blur background, Colour pop and Upscale) asks before anything is fetched (the question starts on "Not now", and the keyboard goes back to the tool when it is answered) and sends nothing to the model host while the answer is no, the On-device models dialog and its File menu entry, then two tiny hand-made ONNX models (`syntheticModel.cjs`: a mask, and an upscaler that makes every pixel a block of pixels) through the real worker, the real ONNX runtime and the GPU (exact mask, exact tile, model kept for the next picture), on the dev server also the whole job layers (install into IndexedDB; cut-out PNG with real transparency; undo and restore; the blur leaving the subject exactly as it was, smoothing the wall behind it, keeping the opacity, and asking the model only once for two tries; the colour pop leaving the subject exactly as it was, turning the wall behind it grey, fading it, asking the model once for the two tries and leaving a grey wall alone; the upscaler's tiles meeting exactly at 2x and 4x, transparency kept without a dark fringe, a JPEG staying a JPEG, Cancel ending the worker and the next job starting a new one); on a production build also that the service worker keeps the runtime file and the worker runs with the network off |
| `a11y.cjs` | what only a real browser can show about keyboard and screen reader use: the first Tab from the page (also after a reload) lands on a control and not on nothing, the design canvas is a named stop in the tab order where Tab walks the elements and then moves on and Shift+Tab comes back, with a frame while the keyboard has it; closing About and the shortcuts dialog gives the keyboard back to what opened them, and Back up & restore takes the keyboard in and gives it back to the Account button; one `h1` naming the design in the toolbar and no gaps between heading levels; the toolbar stays the only banner while the Share panel is open; a rail tab never points at a panel that is not on the page; the list of shortcuts can be reached by Tab; the top bar's labels (at rest and under the pointer), the dashboard headline and the account initial reach their contrast, measured from the pixels; no button, tab or field in the editor is under 24 × 24 px with another close by (WCAG 2.5.8), the page strip's options button included; every page's options button has a name of its own ("Page 2 options") and the add tile's caret is "Add page options" |
| `dashboard.cjs` | start from a template, "Create new design" from the editor, create dialog search, trash and restore, folders, brand kit, and that the dashboard keeps its layout (one row of shortcut tiles, the brand page's add-colour button) after a visit to the editor and its dialogs in the same page: CSS class names are global and a stylesheet that was loaded stays loaded, so two packages styling one class would change each other's screens depending on what was opened first (`src/styles/classNames.test.ts` guards the same thing statically) |
| `backup.cjs` | Back up & restore with two browser profiles: the first save asks the browser to keep the library (once), a library of two designs, a folder and an upload is backed up (one ZIP, read back independently of the app), an empty second profile restores it (the review says what will be added, the designs come back under their own ids with their previews, the upload is whole), restoring again says there is nothing to restore, a PNG is refused as not a backup, a third profile on a phone-sized screen restores a backup with one damaged design and reports it, and no console errors |
| `migrate.cjs` | designs and a library that another version of Craftly stored, written straight into IndexedDB (the frozen designs of `src/test/fixtures/schema` and one that says it is version 99): the design of the first release with every field opens and drawing it writes nothing, the newer one is refused with a screen that says so and is left as it was, starring it still works, copying it is refused with the reason, a backup holds it exactly as stored; then a second tab upgrades the database while an edit waits for the autosave: the edit is written first, this tab says so and lets go, and after a reload the older code refuses the library that was upgraded and leaves every record as it was |
| `update.cjs` | (production build only; it starts a server of its own for `dist-e2e`, under the README's Content-Security-Policy) what happens to tabs that are open when a new build is published: build B (build A with another id, one more file and one lazily loaded chunk gone from the server, as a real build renames its files) installs and waits while two tabs keep running A, both tabs are asked to reload, a tab opened after the update gets B's page and is not asked, Reload in one tab saves an edit that was not saved yet, switches to B and reloads once, the other tab is not reloaded behind its back and still gets the file the server no longer has from the build that was kept, and after build C the build before the previous one is dropped |
| `offline.cjs` | (production build only) the service worker stores the build, then editor, dashboard and a saved design work with the network off, and the Back up & restore dialog (code that loads on first use) opens and makes a backup |

Together the journeys hold 147 checks: 130 run on the dev server and 143 on a production build (with `OFFLINE=1`), since a few belong to one or the other. The video checks of `animated-export.cjs` record in real time and need the tab in front, so a very busy machine can fail one of them once: run `node e2e/animated-export.cjs` alone before you suspect the app.

`ml-real.cjs` is not part of `npm run e2e`: it downloads the real models once (the background remover is 88.1 MB, the upscaler 4.9 MB), keeps them in a browser profile in the temp folder, runs Remove background on a drawn photo, Blur background on one with a wall of dots (the mug unchanged, the dots gone, no halo, a second try without the model; a cut-out sticker left alone; a 12-megapixel photo, with a watch on how long the page is blocked), Colour pop on a mug in front of a wall of strong colour (the wall grey, the mug unchanged, a faint rim, the faded style without the model, a sticker left alone, a 12-megapixel photo) and Upscale on a small soft one, and checks the results (the upscaled edges against a plain stretch, a transparent picture for a dark fringe), printing the toasts, the console lines and the GPU's limits when a job fails. `ONLY=upscale`, `ONLY=remove-background` or `ONLY=blur-background` or `ONLY=colour-pop` runs one tool and downloads only its model (the three background tools share one). Run it with `node e2e/ml-real.cjs` when you want that proof. `ML_PROFILE` names the browser profile folder that keeps the models (default: `craftly-ml-profile` in the system temp folder) and `FRESH=1` deletes that folder first, so the models are downloaded again.

`ml-probe.cjs` (`MODEL=path/to/model.onnx node e2e/ml-probe.cjs`) tries any model file on this GPU before it is wired into the app: its inputs and outputs, the session, timed runs at a tile size (`DIM`, `RUNS`), and a check against a reference output (`REF_IN`, `REF_OUT`, two `.npy` files). It needs a production build to be served.

Settings (environment variables): `BASE` the app URL (default `http://127.0.0.1:5173`), `CHROME_PATH` a browser executable, `HEADED=1` to watch, `E2E_DIST` the production build that `update.cjs` serves (default `dist-e2e` in the project folder, built as described below), `E2E_OUT` where screenshots go (default: a `craftly-e2e` folder in the system temp directory; a failing step saves `NN-FAIL-....png`).

The store handle `window.__editor` exists in the dev server. After you edit source files while the dev server is running, restart it before running the journeys: the job-layer steps of `ml.cjs` import the app's modules by their plain URLs, and once the server has reloaded a module that many others depend on (`core/color.ts`, say) it hands the app those modules under `?t=` URLs, so the step and the app would hold two separate stores and the four steps fail with "That picture could not be read." A freshly started server passes. To run the journeys against a production build, build with `VITE_EXPOSE_STORE=1 npx vite build --outDir dist-e2e` (a `dist-` folder is not watched by the dev server, so it can keep running meanwhile) and serve it with `npx vite preview --outDir dist-e2e --port 4174`. The offline journey needs `OFFLINE=1`:

```bash
BASE=http://127.0.0.1:4174 OFFLINE=1 npm run e2e
```

To check a build that is published in a sub-folder, build with that base (`npx vite build --base=/craftly/ --outDir dist-sub`; in Git Bash put `MSYS_NO_PATHCONV=1` in front, or the shell rewrites `/craftly/`), serve it with `npx vite preview --base=/craftly/ --outDir dist-sub --port 4177`, and give the journeys the folder in `BASE`: `BASE=http://127.0.0.1:4177/craftly node e2e/journey.cjs` (and `dashboard.cjs`, `ml.cjs`, `offline.cjs`). On 2026-11-07 these four passed from `/craftly/` with 19, 7, 13 and 4 checks; the others were not run there.

In PowerShell a variable is set first, on its own: `$env:BASE = "http://127.0.0.1:4174"; $env:OFFLINE = "1"; npm run e2e` (and `Remove-Item Env:OFFLINE` afterwards).
