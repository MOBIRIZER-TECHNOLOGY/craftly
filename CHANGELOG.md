# Changelog

All notable changes to Craftly are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- **Remove background**, the first AI tool, in a new **Tools** tab of the Edit image panel. A small neural network (ISNet general-use, Apache-2.0 licence) runs on your own graphics card, in a Web Worker, through ONNX Runtime Web (WebGPU), so the photo never leaves the device (about five seconds per photo on an integrated Intel GPU). The result is a PNG with real transparency, applied as one undo step; **Restore original** brings the old picture back, also after saving and reopening a `.craftly` file. Needs a browser with WebGPU and half-precision shaders (Chrome and Edge 113+, Safari 26+, Firefox 141+ on Windows); without them the tool says so. Locked photos are refused up front, Cancel works until the picture is applied, and a failure shows a plain sentence in the app and the technical reason in the console.
- **Upscale**, the second AI tool, next to Remove background in the Tools tab: a photo becomes 2x or 4x larger, with the sharpness that a small or soft photo lacks drawn back by Real-ESRGAN general x4 v3 (BSD-3-Clause licence), a 4.9 MB model that runs on your own graphics card in the same worker. The photo is worked on tile by tile (equal tiles of at most 256 pixels, with 16 pixels of its surroundings so tiles meet without a seam), with a progress bar, the time left and Cancel. The photo keeps its size on the page and its original ("Restore original"), transparency is kept without a dark fringe, a JPEG stays a JPEG, and a result over 25 megapixels is refused before anything is downloaded. It needs WebGPU but not half-precision shaders.
- **Blur background**, the third AI tool, in the Tools tab: it keeps the subject of a photo exactly as it was and blurs everything behind it, light, medium (the default) or strong. It uses the background remover's model, so there is nothing more to download. The blur is worked out in the page from the background's own pixels only (the subject's colours do not bleed into it), on a coarser grid so that 25 megapixels cost about a second of arithmetic, and in pieces, so the screen stays alive and Cancel works. The model's answer is kept for the photo: after Undo, another try with another strength takes under a second. Transparency is kept, a JPEG stays a JPEG, and a photo whose surround is already transparent is left alone, with a message.
- **Colour pop**, the fourth AI tool, in the Tools tab: the subject keeps its colours and everything behind it goes black and white, or faded (60 % of the colour taken out). It uses the background remover's model, so there is nothing more to download, and the arithmetic is the blur's path with simpler maths: the grey is the one of the Filters panel's black and white, the subject is never touched, and where the model's outline is soft the colour fades out over the same pixels. A photo whose background has no colour (black and white already, transparent, or only the faint rim of a cut-out) is left alone, with a message. The model's answer is kept, so after Undo another try with the other style takes under a second; Remove background, Blur background and Colour pop share it.
- **File > On-device models**: what is installed, with size, licence, credits and source; download, remove, or add a model from a file (for a computer that is offline); how much room is used and whether the browser will keep the models.
- Each model (88.1 MB for the background model, 4.9 MB for the upscaler) downloads only after you agree in a dialog that names its size and host (huggingface.co). The file is pinned to one repository commit and checked against its size and SHA-256 before it is kept, the request carries no cookies or referrer, and the file lives in its own IndexedDB. `VITE_CRAFTLY_MODEL_BASE` points the app at your own host instead.
- The 28.7 MB ONNX runtime file is left out of the first-visit download. The service worker stores it on first use, in a cache that survives app updates, so the tool then works offline.
- `docs/ON-DEVICE-AI.md` (design, decisions, why the first model failed and was replaced, the model manifest and licence rules, failure modes and the tests that pin them), `e2e/ml.cjs` (the real runtime and GPU in the browser, with a hand-made model), `e2e/ml-real.cjs` (the real model) and `e2e/ml-probe.cjs` (tries any model file on this GPU before it is wired in: a tile size, repeated runs, and a check against a reference output), a progress bar in the UI kit, the `updateElementsOnPage` store action and `ImageElement.originalSrc`.
- **Ellipse** in Elements > Shapes, next to the circle, and the search words *oval*, *elliptical*, *round* and *rectangle* for the shapes that people look for by those names.
- A component test suite on jsdom and React Testing Library, with a harness for the canvas, IndexedDB, observers and image loading (`src/test/`). 6,121 tests in total, 99.4 % statement coverage; `npm run coverage` fails when statements, branches, functions or lines drop below 95 %.
- The MIT `LICENSE` (the copyright line reads "Craftly contributors"; put your own name there if you prefer), and `npm run notices`, which generates `THIRD-PARTY-NOTICES.md`.
- A feature comparison with Canva and the research behind it (`reports/`, `research_notes/`): what is missing, why, and how local models, an image server and WebCodecs could close the gaps.
- Ctrl+B, Ctrl+I and Ctrl+U in the shortcuts list (they already worked).
- **Hosting headers and a verified Content-Security-Policy.** `public/_headers` (read by Netlify and Cloudflare Pages) sets the caching and the safe headers. The README gives a policy that every browser journey, the offline one included, passes against, on a production build served with it enforced (it needs `'wasm-unsafe-eval'` for the ONNX runtime, `data:` fonts, and `'unsafe-inline'` for styles because of the print frame); the download of a model from Hugging Face is not one of the journeys and is said to be unverified.
- **ESLint** (`eslint.config.js`: typescript-eslint, React hooks and jsx-a11y rules; `npm run lint`, run by CI with no warning allowed) and **Prettier** (`.prettierrc.json`, `npm run format`, checked by CI with `npm run format:check`). Prettier was applied to the code on 2026-11-07: it changed about 300 of 600 files and nothing in how they behave; stylesheets, documents and `src/data` are laid out by hand and skipped. The first run found 123 errors in 673 files. Unused imports, constants and variables were removed, some `let`s became `const`, and a comment that began with `global` (it was read as a directive that declares globals) was reworded. The accessibility patterns that are deliberate (a tab list whose tabs are the focusable parts, a dialog backdrop that closes on a click while the keyboard has Esc, scrolling regions that take the focus) now say why, where they are.
- Tests for two things that breaking the code on purpose showed nobody was checking: the 1.2 s window in which edits with one key merge into one undo step, and the 40 and 8,000 px limits of a custom size (`src/test/README.md` tells how the check was done).
- `docs/VERIFICATION.md`: how the app was verified from a clean copy (install, audit, types, lint, tests with coverage, the browser journeys on the dev server, on a production build under a strict Content-Security-Policy and from a sub-folder, Lighthouse, mutation spot checks), the results, what the coverage number counts, and what was not checked.
- A `robots.txt` that allows crawling (without one, a host that answers unknown paths with the home page makes Lighthouse call the SEO score invalid); Lighthouse now reads 100 for accessibility, best practices and SEO on the production build.
- A `<noscript>` message in `index.html`, a release checklist in `CONTRIBUTING.md`, a `.gitattributes` (LF in the repository, as `.editorconfig` says) and `dist-*` in `.gitignore`.
- README screenshots, a deploy guide, privacy and credits sections; `docs/ROADMAP.md` (what to improve next and how AI features would fit); `CONTRIBUTING.md`, `SECURITY.md`, `.editorconfig`, `.nvmrc` and Node `engines`; a GitHub Actions workflow, Dependabot configuration and issue and pull request templates.

### Changed

- The Tools tab and the On-device models dialog handle several models: each tool checks what its own model needs of the graphics card (a card without half-precision shaders still gets the upscaler), one notice covers a browser that cannot run any of them, and one "Original photo kept" row restores the original for any tool. Only one job runs at a time, whichever tool it is.
- The Tools tab says once, at the top, that "A photo tool is working on this photo" (it used to say so under every other tool), and the download of a model that two tools share is shown under the tool that asked for it. The On-device models dialog says the remover's model also finds the subject for the blur and the colour pop.
- The coverage gate is 95 % (it was 90 %) on statements, branches, functions and lines.
- The on-device browser journey (`e2e/ml.cjs`) no longer assumes that the app is at the root of a site, so the journeys can be run against a build published in a sub-folder.
- `npm audit` reports no vulnerability, dev tools included: the one finding, in the `minimatch` that ESLint and typescript-eslint use, is overridden with the patched 11.x (see `CONTRIBUTING.md`), and CI audits the packages that ship.
- The CI workflow also builds a production copy and runs the browser journeys against it, the offline one included, and keeps the server logs with the screenshots when a check fails. `engines.node` names what the test tools need (Node 22.22.2+, 24.15+ or 26+); the dev server and the build alone also run on Node 20.19+.
- The documents were checked line by line against the code and corrected: the scope statements that still said there is no AI, API and file names that did not exist, the folder maps, the counts, the Node range and the file sizes (README, CONTRIBUTING, SECURITY, `docs/`, `e2e/README.md`, `src/test/README.md`).
- The About dialog says that the AI tools are the one exception to "nothing is sent": with your permission they download a model once, and your designs and photos are never sent.
- **Colours and sizes that failed the contrast and click-target rules are fixed** ([`docs/ACCESSIBILITY.md`](docs/ACCESSIBILITY.md), with a before and after picture). The top bar's gradient is deeper (`#0f766e`, `#2563eb`, `#7c3aed`), so its white labels reach 5.2:1 or better (they were 2.1 to 4.0), and the bar's hover, pressed and open states darken it instead of lightening it. The small grey text colour `--c-ink-4` is `#696d76` (it was `#9aa1ad`, 2.6:1; it reads 4.5:1 or better on a hovered row too); the old grey is `--c-ink-5`, for icons, borders and lines. The dashboard headline, the "Suggested" badge, the text of the brand kit preview (wherever the full ink can reach 4.5:1 on the kit's colour) and the default colour of an avatar (for any name) were darkened the same way, and the options button of a page is 24 × 24 px (it was 22). The success and danger badges, the solid ones included, have text and fill colours that reach 4.5:1 (`--c-success-ink`, `--c-danger-ink`, `--c-success-solid`, `--c-danger-solid`, `--c-info-solid`), and every page's options button has a name of its own, "Page 2 options", where they were all called "Page options" (the caret of the add tile is "Add page options"; the menu a button opens is named like it). Words in the danger red (error messages, the delete entries of menus, Empty trash and Delete forever) use the darker `--c-danger-ink` (3.9 to 5.2:1), and the danger button rests on `--c-danger-solid` (3.9 to 4.5:1), with its hover and pressed colours darkened to keep the steps. The outline of text fields, selects, checkboxes and the off switch is the new `--c-field-border` (3.2:1 on white, it was 1.5:1) and turns darker under the pointer, and the amber of icons (the favourite stars, the warning marks) is the new `--c-warning-ink` (5.0:1, it was 2.2:1). `--grad-brand`, `--grad-text` and `--c-ink-4` are values of the design contract in `docs/DESIGN.md`, which lists the new ones.
- `src/styles/tokens.test.ts` holds the contrast of the colours that carry words and the top bar's tints, and keeps the contract in `docs/DESIGN.md` equal to `tokens.css`; `e2e/a11y.cjs` measures the top bar's labels (at rest and under the pointer), the dashboard headline and the account initial from the pixels, and checks every button, tab and field in the editor against the 24 px rule.

### Fixed

- **The dashboard changed its layout after a visit to the editor.** CSS class names are global and a stylesheet that has been loaded stays loaded, so two screens that gave one class name different rules changed each other, depending on what had been opened first: the dashboard's row of quick-create tiles broke into two columns once the editor's keyboard shortcuts dialog had been opened (both were `.cf-shortcuts`), and the brand kit page and the editor's Brand tab shared five `.cf-brand__*` names with different sizes. The dashboard's names are now `cf-dshortcut…` and the editor's Brand tab's `cf-brandtab__…`; `src/styles/classNames.test.ts` fails when two packages style one selector, and a step of `e2e/dashboard.cjs` goes to the editor, opens its dialogs and comes back in the same page. A fresh page never showed it, which is why the other checks missed it; it was found by walking the app in a real browser.
- **Keyboard users can reach the editor.** Tab pressed on the page or on the canvas always selected the next element and moved no focus, so nobody without a mouse could get to the toolbars, menus or panels. Tab now walks the elements of the page only while the canvas has the focus and moves on after the last one; the canvas is one named stop in the tab order ("Design canvas") with a frame while the keyboard has it.
- More from the accessibility audit ([`docs/ACCESSIBILITY.md`](docs/ACCESSIBILITY.md); axe-core reported 10 rules, now 4): a rail tab no longer names a panel that is not on the page; the Projects tab's "Show" tabs have their panel; the list of shortcuts can be reached and scrolled by keyboard; the editor has a heading to move by and the panels and empty states have the right heading levels; the Share panel and Find and replace no longer add a second banner landmark; the page counter and the brand colour swatches have labels a screen reader can read; "Add page numbers" and "Rename design: <title>" contain the text that is visible; closing About or the model download question gives the keyboard back to what opened it; the download question opens on "Not now", so a doubled Enter cannot agree to 88.1 MB.
- On Windows the dev server (`npm run dev`) could sit at two or three CPU cores for as long as it ran, with nobody using it. It started after a coverage run or a build into a folder inside the project (`dist-e2e`): a file watch on a folder that has been deleted keeps sending "rename" events there, about 100,000 a second (plain `fs.watch` does it in Node 24 and 26 on Windows 11, with no Vite involved). The dev server now leaves `coverage/` and the `dist*` folders alone (`server.watch.ignored` in `vite.config.ts`), and `src/test/devServerWatch.test.ts` starts a real Vite server and fails when it holds a watch on them.
- Shift-dragging with the shape tool created the unconstrained rectangle instead of the square shown in the preview.
- Dropping several images at once made each one replace the one before.
- Shift+Tab with nothing selected went to the second-to-last element instead of the last.
- A line break typed straight into the text box was lost when the edit was saved.
- "Make a copy and resize" kept the old unit (a US Letter copy stayed in pixels).
- Pressing Escape in the colour picker's hex field still applied a typed 3-, 4- or 8-digit colour.
- Text with a very slight curve (under 0.52) crashed or vanished.
- A graphic written as a self-closing `<svg/>` produced broken SVG on export.
- Importing a project file lost the type of images that had none recorded.
- Title case ignored accented initials.
- An error while painting a frame left the WebM recording hanging with Cancel disabled; it now stops with a message.
- The upload message read "1 file was skipped because they are not images".
- The alt-text dialog said the description is used in all exports; only SVG downloads carry it, and the text now says so.
- A late text selection in number fields could erase digits typed quickly.
- Loading a side-panel tab or the icon library in the background reported an unhandled error when the load failed.

## [0.1.0] - 2026-11-05

First complete version.

### Added

- Dashboard with search, recent designs, projects with folders and stars, a templates browser, brand kit and trash.
- Canvas editor: selection, move, resize, rotate, group, align and distribute, snapping, rulers and guides, zoom and pan, undo and redo with version history, find and replace, multi-page designs with a grid view.
- 72 templates (141 pages), 46 shapes (45 drawings and a rounded square) plus lines and arrows, 2,000+ icons, 161 illustrations, 44 procedural photos, frames and photo grids, 136 backgrounds, tables, charts and freehand drawing.
- Rich text with 44 bundled font families, nine text effects and curved text.
- Image upload, crop, filters, adjustments, duotone, shadow, blur, corner radius and borders.
- Animation: element effects, page transitions, a full-screen presenter with auto-play.
- Export to PNG, JPG, PDF, SVG, multi-page ZIP, animated GIF and WebM video, and `.craftly` project files.
- Installable, offline-capable app (service worker), responsive layout with a bottom tool dock on narrow screens.
- 586 unit tests and 83 scripted browser checks.
