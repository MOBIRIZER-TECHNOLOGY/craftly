# Changelog

All notable changes to Craftly are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## Unreleased production-readiness fixes

- Editor saves compare revisions in one transaction. Stale tabs can recover their drafts without overwriting newer work or recreating a deleted design. The document commits before thumbnail rendering. Navigation and updates handle failed saves explicitly, and updates also wait for confirmed writes.
- Live sharing uses a separate owner key. The server rejects malformed request targets, applies default room and peer limits, persists edits before acknowledging them, and checks whether room storage is writable. Same-tab reloads retain queued edits, rejected edits get recovery copies, and collaborators can load shared uploads.
- Portable project files and library backups omit live links. Project import stages images before committing the design, and export reports missing images. Service-worker cleanup preserves unrelated same-origin caches.
- See [verification](docs/VERIFICATION.md#production-readiness-regressions) for the 16 regression cases and remaining release checks.

The three actions (`checkout` 4.4.0, `setup-node` 4.4.0, `upload-artifact` 4.6.2: the latest releases of the major version in use, which are the commits `v4` pointed to on 2026-11-13) are now named by their full commit, with the version in a comment. On Windows a process cannot be asked to stop, so the clean exit is checked on Linux and macOS only. The README now says that `server:build` uses the esbuild that Vite brings along, which is not named in `package.json`.

## Unreleased fixes from a second review of the code (2026-11-13)

- **The live server no longer drops every connection after a minute.** The server pings each connection and drops one that did not answer by the next round, but it listened for the answers in a place that an upgrade handled by hand never reaches, so no answer was ever seen: every browser lost its connection after 30 to 60 seconds, came back, and was sent the whole design again. The answer is now listened for on the connection itself (`src/server/live.ts`; the interval is the new option `heartbeatMs`).
- **A room leaves the server's memory when its connection went away while the room was being read.** Such a room had nobody in it and nothing that would ever take it out again, so a visitor who opened and closed a connection to each room kept them all in memory.
- **A copy of a shared design is a design of its own.** "Make a copy" and "Resize a copy" copied the room and its keys with the design, so the copy opened as the shared design and every change to it went to everybody in the room (`duplicateDesign` in `src/core/library.ts`).
- **An SVG download writes only the line ends and corners SVG knows.** The two words of a stroke went into the markup as they were, and a design from a file is not checked that far down: text with a quote in it ended the attribute and began markup of its own, a script included, in every SVG a person downloaded from that design.
- **Resizing a selection with no height or no width keeps real numbers.** Two lines side by side make a selection without height; dragging a handle divided by it, and positions and sizes that are no number were written into the elements and saved (`scaleOf` in `src/editor/canvas/resize.ts`). A side that had no length is now left as it is.
- **What is dropped on the canvas is checked like a file.** Any page can put data of Craftly's type on a drag. It went onto the page as it was; now only elements the renderer can draw are kept, without pictures from the web, a dropped picture must be one of the editor's own kinds and have a size, and a background must be a fill (`readDragPayload` in `src/editor/insert.ts`).
- **A graphic is plain drawing or it is left out.** The markup of a graphic was only checked to be text where a design comes in, and an SVG download cleaned it with a list of things to take out, which could be walked around (a script behind a prefix, a page in another namespace, an address written with an escape). A graphic whose markup is anything but plain drawing (`svgProblem`) is now not accepted from a project file, a backup, the clipboard or a drop, and counted with what was left out; an SVG download writes a graphic only when all of it is plain drawing and leaves it out with a warning otherwise. Every graphic the app makes passes. The ids of a graphic are renamed with a function, because an id such as ``$` `` stood for the markup around it.
- **Working together: an image the server will never take no longer stops everything.** A failed upload closed the connection and tried again about twice a second for good, with every later edit waiting behind it. An image the server refuses (too big, the room is full of images, gone) is now given up like an edit the server refused, with a recovery copy and a message, and the rest goes on; a failure that may pass is tried again with waits that grow to ten seconds.
- **Working together: edits that never reached the server are not lost without a word.** The edits that wait are kept for a reload of the same tab only. A tab that was closed with edits waiting now leaves a mark, and when the design is opened again the version on the device is kept as a recovery copy in Projects, and said so, before the shared version is shown.
- **Working together: a duplicated tab goes on under a name of its own.** A tab duplicated while it had edits waiting shared its name and batch numbers with the first: the two closed each other's connection for good, and the server took a batch of one for a batch of the other. A tab that is told another connection took its place takes a new name and sends its waiting edits under it.
- **Working together: one recovery copy for refused edits.** A room that is full refuses every edit, and each one added another copy of the design to the library and another message. There is one copy for a design in a tab, brought up to date each time, and one message.
- **Working together, smaller things.** An operation that moves an element into something that is not a group leaves it where it was (it was deleted). A yes to connecting to a new server is for one link, not for the next one opened in the same tab. A design larger than one batch may carry can be shared (its size in bytes is the limit).
- **After an update, an offline start opens the new version.** The service worker asked every cache for the app's page and got the one of the build before, which cannot open a database the new build has upgraded. It asks its own cache first. On a host that sends `/index.html` on to `/`, the page is stored as an answer of its own, so the first offline reload works.
- **An upload is saved when the browser has stored it.** Single writes to the library were reported done when the write was taken, but a browser without room says so only when the transaction ends: a picture could be on the page and not in storage. Writes and deletions now wait for the transaction and always fail with an error, so the "out of room" message is shown where it was lost before.
- **A backup brings back only uploads that are pictures.** A backup made by hand could store any file under any type in the app's storage.
- **A drag ends, whatever happens to the pointer.** A second finger on the canvas during a drag took the drag over and left the undo step open, which switched undo off until the design was opened again; it is ignored now. A drag that loses its pointer ends like a cancelled one, and so does the drag of a guide.
- **Copy, cut and paste stand back where the keys do.** With a dialog open or while presenting, Ctrl+X deleted the selection behind it and Ctrl+V pasted into the page underneath; they are left to the browser there.
- **Space no longer counts as held after the window lost focus**, so clicks do not pan after coming back.
- **An edit made while a save was running is written when the editor closes** (it was dropped when the editor closed before that save ended).
- **Zooming while editing text keeps the caret and the selection**: the sizes are changed where they are, and the text is not built again.

## Unreleased security fixes from a review of the code (2026-11-11)

- **A design never loads a picture from the web.** Nothing in the editor makes a picture that points to the web, but a design from outside could carry one, and opening it would ask a server of somebody's choosing for the picture, which tells them who opened the design, from where and when. Such a picture is now taken out where a design comes in: a project file and a backup (the import says how many), pasted elements, and a shared design (the server and the browser refuse the operation). The loader does not fetch one that got through, and the SVG download no longer fetches pictures either (`src/core/imageSources.ts`). Which address counts is asked the safe way round: only the four kinds the editor makes (`asset:`, `builtin:`, `data:`, `blob:`) are loaded, because a browser reads many spellings as an address on the web (`https:\\host`, `/\host`, a tab inside `https`) and the first version, a list of spellings to refuse, missed those. The crop view and the thumbnail of a background went round the loader and handed an address to the page as it was; they have none for such a picture now, and the thumbnail writes its address into CSS with escapes, so it cannot carry a second one.
- **What is pasted is checked like a file.** Elements on the clipboard come from other pages and programs too. They went into the design as they were; they are now checked like the elements of a project file, and what is no element is left out.
- **A link to a shared design asks before it connects to a server that is new on this device.** A link names its server, and anybody can make a link. The page says which server it is and what joining means; the servers a person shared on or said yes to, the one the site was built for, and a design that was joined before do not ask (`src/editor/live/knownServers.ts`).
- **The service worker keeps only the app's own page as the offline shell.** It kept whatever answered a navigation: an error page of the host, or `/robots.txt`, became what the app opened with when offline. It now keeps an answer only for the app's address, when it is a page and a success, and opens the copy it has when the host answers with a server error.
- **The Content-Security-Policy is switched on** in `public/_headers`, after a model download was tried under it. A site that uses a live server adds that server's addresses to `connect-src`.

## Unreleased fixes from testing by hand (2026-11-11)

- **Text wraps at the edge of the page.** A text box that grows as wide as its text used to keep growing past the page: a sentence typed into a new text box ran off the right edge, with the handle to make it narrower out of reach. A box that was inside the page now becomes a wrapping box when its text, or a larger font size, would take it past the left or right edge. It keeps the side its alignment holds (left edge, right edge or middle) and is one step to undo. A box that already reaches past the page, a turned one and one inside a group are left alone, and so is every text of a design that is opened.
- **The text of a chart stays inside the chart.** A legend that is wider than the chart takes up to three lines (the plot moves down), names that are still too long are cut with an ellipsis, the names beside a bar chart get up to two fifths of the chart, crowded categories are named every few, values that would run into each other are left off, and numbers from a million on are written short (`2.5M`, `1.23B`, `1e20`). The page and the SVG download decide this in one place (`src/render/chartText.ts`), so they draw the same chart. A chart whose text fitted is drawn as before.
- **A long text no longer stalls the app.** Breaking a text into lines took the tokens off the front of one array, which costs the length of the array each time: a megabyte of text took 4.5 seconds for one layout and most of a minute to import. The lines are now read by index (`breakIntoLines` in `src/render/textLayout.ts`), and eight times the text takes about six times as long where it took thirty-five.
- **Project files: what is left out is said, and limits a file cannot argue with.** An import says how many items could not be read and were left out, where it used to say only "Imported". A title is cut to the 120 characters the title field allows. Groups inside groups are read 32 deep and no deeper (a file nested thousands deep was refused by the browser with an error of its own). An error that is not about the file is told in words ("It could not be saved on this device...") and no longer in the browser's.
- **A model download carries on where it broke.** A connection that breaks or closes early in the middle of a model file is taken up again with a request for the rest only, up to four times with a growing pause, and what arrived is kept for the next try when those are used up. A server that does not answer with the part that was asked for is asked for the whole again; a cancelled download and a wrong file keep nothing; the file is still checked as a whole against its pinned size and SHA-256 (`src/ml/download.ts`).
- **Working together: a person is told when the text they are typing in is deleted by someone else.** The editing box used to close without a word and the next keys ran shortcuts of the canvas.
- **On a phone the side panel folds away when something is added from it**, so that what was added can be seen (`src/editor/foldPanelOnInsert.ts`). A panel of options for the selection stays open.
- **Small things.** A rotation beyond a full turn is the turn that is left over (725° is 5°, it used to become 0°). Paper sizes are named as the paper is ("210 × 297 mm" for A4, which is stored as 794 × 1123 px and was shown as "210.08 × 297.13 mm"). The table picker says "1 row by 1 column". The chart panel says that a negative number gets no slice in a pie or donut.
- **A double click on a table or a chart opens its data.** For a table the keyboard goes into the cell that was double-clicked, with its text selected. Before, a double click did nothing and what was typed next ran the one-key shortcuts of the canvas (a circle, a line, a text box).

### Added

- **Remove background**, the first AI tool, in a new **Tools** tab of the Edit image panel. A small neural network (ISNet general-use, Apache-2.0 licence) runs on your own graphics card, in a Web Worker, through ONNX Runtime Web (WebGPU), so the photo never leaves the device (about five seconds per photo on an integrated Intel GPU). The result is a PNG with real transparency, applied as one undo step; **Restore original** brings the old picture back, also after saving and reopening a `.craftly` file. Needs a browser with WebGPU and half-precision shaders (Chrome and Edge 113+, Safari 26+, Firefox 141+ on Windows); without them the tool says so. Locked photos are refused up front, Cancel works until the picture is applied, and a failure shows a plain sentence in the app and the technical reason in the console.
- **Upscale**, the second AI tool, next to Remove background in the Tools tab: a photo becomes 2x or 4x larger, with the sharpness that a small or soft photo lacks drawn back by Real-ESRGAN general x4 v3 (BSD-3-Clause licence), a 4.9 MB model that runs on your own graphics card in the same worker. The photo is worked on tile by tile (equal tiles of at most 256 pixels, with 16 pixels of its surroundings so tiles meet without a seam), with a progress bar, the time left and Cancel. The photo keeps its size on the page and its original ("Restore original"), transparency is kept without a dark fringe, a JPEG stays a JPEG, and a result over 25 megapixels is refused before anything is downloaded. It needs WebGPU but not half-precision shaders.
- **Blur background**, the third AI tool, in the Tools tab: it keeps the subject of a photo exactly as it was and blurs everything behind it, light, medium (the default) or strong. It uses the background remover's model, so there is nothing more to download. The blur is worked out in the page from the background's own pixels only (the subject's colours do not bleed into it), on a coarser grid so that 25 megapixels cost about a second of arithmetic, and in pieces, so the screen stays alive and Cancel works. The model's answer is kept for the photo: after Undo, another try with another strength takes under a second. Transparency is kept, a JPEG stays a JPEG, and a photo whose surround is already transparent is left alone, with a message.
- **Colour pop**, the fourth AI tool, in the Tools tab: the subject keeps its colours and everything behind it goes black and white, or faded (60 % of the colour taken out). It uses the background remover's model, so there is nothing more to download, and the arithmetic is the blur's path with simpler maths: the grey is the one of the Filters panel's black and white, the subject is never touched, and where the model's outline is soft the colour fades out over the same pixels. A photo whose background has no colour (black and white already, transparent, or only the faint rim of a cut-out) is left alone, with a message. The model's answer is kept, so after Undo another try with the other style takes under a second; Remove background, Blur background and Colour pop share it.

- **Back up & restore** (account menu): one ZIP with every design (the trash too), uploaded picture, folder, saved version and the brand kit, and the way back. - **Versioned storage and migrations: saved designs outlive releases** ([`docs/MIGRATIONS.md`](docs/MIGRATIONS.md)). The database is opened through numbered steps in one upgrade transaction; a tab on this release lets go of its connection when another tab upgrades (after writing the open design), says "Craftly was updated in another tab. - **Pen tool**: vector paths made of points and curves (the "vector gaps" item of [`reports/Craftly versus Figma.md`](reports/Craftly%20versus%20Figma.md)). Choose **Pen** in Tools or press `P`. A click places a corner point; a press that is dragged pulls a curve out of the point (a handle on each side; a drag of under 3 px stays a corner); a click on the first point of a path of three or more points closes it, and a click on the last point, `Enter`, `Esc` or choosing another tool ends it open; `Shift` keeps a side at a multiple of 45 degrees and `Backspace` takes the last point back. Undo belongs to the path while it is placed: `Ctrl+Z` and the Undo button take the last point back too and never reach into the design under it (Redo is off until the path is finished), and choosing another page in the middle of a path finishes it on the page it was drawn on, leaving the new page, the Pen and the selection as they were. While it is placed the path is drawn as a preview (the path so far, the side the next click would make, the handles of the last point and a mark on the first point when a click would close the path), and it becomes one undo step. An open path is a line in the colour and width of the Draw options, a closed one is filled with that colour and has no outline. Nothing in the stored formats changed: a path is the existing `shape: "path"` shape (path data in a 0 to 100 box that is stretched to the element), so no migration was needed, and every export, the renderer and the animations treat it like any other shape (SVG export writes the real curves).
- **Edit points**, for any path of straight sides and cubic or quadratic curves in one piece (the Pen's and the freehand Draw tool's): the shape toolbar has an **Edit points** button, and `Enter` or a double click on a selected path does the same. The points and handles are drawn over the path: click a point to select it (`Shift` adds or removes one) and drag it, with all the selected points; drag a handle to reshape the curve (`Alt` moves that handle alone and makes the point a corner, `Shift` gives the other handle the same length); click the path to add a point that does not change its shape (and go on dragging it); double-click a point to turn it between a corner and a smooth point; a toolbar of its own (**Corner**, **Smooth**, **Delete point**, **Close path**, **Done**, and a caption that says which point is selected, read out by screen readers as it changes); `Tab` and `Shift+Tab` walk through the points and, after the last one (or before the first), on to the toolbar of the points, so that Corner, Smooth, Delete point, Close path and Done can be reached without a mouse; the arrows move the selected ones by 1 px (`Shift` 10 px), `Delete` removes them (the whole shape goes when fewer than two points would be left), and `Esc`, `Enter`, **Done** or a click elsewhere leaves. Editing changes the element's box to fit the new curve while every point stays where it is on the page, also when the element is turned or mirrored, and each gesture (or run of arrow presses) is one step to undo. A path with arcs, relative commands or several pieces has no Edit points button, and a locked path is not opened (a lock that is set while its points are open closes them).

- **Combine shapes**: select two or more shapes and choose **Combine** in the toolbar (or **Combine shapes** in the right-click menu) for **Union** (one outline), **Subtract** (the shapes in front cut out of the one at the back), **Intersect** (only what they have in common) or **Exclude** (what they have in common taken away). The result is one ordinary path with the fill, border, effects, link and animation of the shape at the back, in the place of the shape at the front, selected, and one undo step. The geometry is done on the Bezier outlines by [paper.js](https://paperjs.org) 0.17 (MIT licence), so curves stay curves, a turned or mirrored shape is combined where it is drawn, and the hole of a ring stays a hole. A result of one piece can be edited with Edit points; a result with a hole or in two pieces cannot yet (it takes colour, size, effects and every export as usual). When nothing is left (Intersect on shapes that do not overlap) a message says so and nothing changes; shapes that were edited while the geometry was loading are left as the person made them, and a geometry file that cannot be fetched says so and can be tried again. Two outlines of 2,000 points each take about a tenth of a second.

- **Connect**, the start of diagrams and flowcharts: select exactly two elements and choose **Connect** in the toolbar (next to Group and Align) or in the right-click menu, and an arrow is drawn from the one selected first to the other. It ends in the middle of the sides that face each other and **stays attached**: moving, resizing or turning either element (or a text that grows when its font arrives) aims the arrow again in the same step of undo; deleting a shape deletes its arrows, and undo brings both back; moving an arrow by hand lets it go; duplicating, pasting, or copying a page keeps copies attached to copies, and combining shapes hands their arrows to the new shape. A shape that is put in a group lets go of its arrows. What lies under it:
- **Live editing, the core and a server** (`docs/COLLABORATION.md`): `src/collab/` holds what several people editing one design at the same time need, as pure code that a server will run too. A change is described as **operations** addressed by id and carrying whole properties (`diffDesign(before, after)`, replayed by `applyOps`): two people who change different properties of one element both keep their change, and for the same property the batch the server applied last wins. A **room** applies each batch in the order it arrives, numbers the revision, answers the sender and tells the others; a browser's **session** keeps what the server has confirmed, its own changes that it has not, and shows the first with the second replayed on top, so someone else's change lands in the middle of its work without taking it away, a refused change disappears, a lost connection loses nothing and nothing is applied twice. What arrives is checked (`checkOps`: shape, sizes, depth) and applying is total: it never throws, ignores what it cannot place, never adds an id twice and never lets a property change what an object is. Checked by the real editor (40 random sequences of 60 actions through the store, each change replayed in both directions) and by a simulation of 210 runs of up to six browsers with random delays, dropped connections and server restarts that must end with every browser showing the server's design (83 deliberate breaks of the core, all caught). - **Blend modes** (2026-11-10, [`docs/BLEND-MODES.md`](docs/BLEND-MODES.md)): any element or group can mix its colours with what is under it in one of fifteen modes (Darken, Multiply, Color burn, Lighten, Screen, Color dodge, Overlay, Soft light, Hard light, Difference, Exclusion, Hue, Saturation, Color, Luminosity), chosen in **Blend mode**, a new box in the Transparency popover of the toolbar (Normal takes the mode away; several elements at once say Mixed when they differ; one undo step).
